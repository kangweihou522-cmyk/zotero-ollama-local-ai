# v0.2.0 验证范围

兼容目标是 Zotero 10.0.8 桌面版，清单允许 `10.0.x`。其他主版本尚未声明兼容，不能只放宽清单版本范围就视为适配完成。

## 已定位的安装问题

用户安装 0.1.0 时出现“可能无法与该版本的 Zotero 兼容”。已确认旧包缺少 `applications.zotero.update_url`。Zotero 官方构建脚本要求 ID、更新地址和最高兼容版本；字段缺失会在清单解析阶段拒绝安装。[10.0.8 校验源码](https://github.com/zotero/zotero/blob/10.0.8/app/scripts/fetch_xulrunner#L243)

0.2.0 补充真实更新地址与 `updates.json`，增加缺失字段、发布元数据一致性和归档结构的回归检查。旧包 ZIP 结构有效，不能仅凭约 25 KB 的大小判断文件损坏。

这些检查验证打包规则，不能单独证明真实 Zotero 接受安装并成功运行全部功能。

## 自动测试覆盖

- 核心：本机地址、设置和模式；标签、短简记、六部分概览的 JSON 校验；安全 HTML；材料来源、截断、上下文预算、思考选项、云模型拒绝和取消。
- Zotero 适配器：模拟 API 验证父条目选择、本地 PDF 缓存、标签追加、简记和概览子笔记、只读库保护、HTTP 选项及取消。
- Style 字段：只修改 Extra 的 `remark:` 行并保留其余内容；已有简记需要明确更新选择；重复字段和并发修改阻止该字段写入。
- 生命周期：模拟宿主验证模块加载、菜单和设置注册、窗口桥接及禁用清理。
- 打包：宿主必需字段、更新清单一致性、XPI 与源码归档。
- Chromium 界面：使用实际 XHTML 内部控件、CSS、脚本和核心逻辑，将 XUL 外层替换为浏览器容器，验证生成、编辑、切换、保存、取消、失败保留草稿等流程；该层不运行原生 XUL 宿主。

当前版本已执行：核心、适配器、生命周期与打包回归 **46 项通过**；Chromium 界面流程 **7 项通过**。运行命令见 [README](../README.md)。模拟界面截图不能证明真实模型的生成质量。

## 原生宿主与实际模型

开发云环境没有预装 Zotero，官方二进制下载地址曾返回代理 HTTP 403。原生测试流程需要使用独立临时 profile 安装实际构建的 XPI，检查真实窗口、原生 HTTP、条目与笔记写入，并记录结果。只有流程成功的执行记录才是宿主安装验证的证据，新增测试脚本本身不代表已通过。

原生测试即便使用回环地址的模拟 Ollama 服务通过，也只验证请求和保存流程。实际模型的 JSON 遵循能力、生成速度、理解和事实准确性仍需在用户本机验证。

Style 互通依据作者公开的 Extra `remark:` 约定，不替换 Style 的原 AI 菜单，也未对用户当前全部插件组合做联合测试。[Style 作者说明](https://github.com/MuiseDestiny/zotero-style/issues/1308)

## 本机验证步骤

1. 在 Zotero 10.0.8 安装 0.2.0 XPI，确认菜单、设置入口和生成窗口可用。
2. 启动本机 Ollama，检测并选择模型，分别生成标签、短简记和结构化概览。
3. 用仅有标题／摘要及带本地 PDF 索引的文献检查来源提示和缺失信息表述。
4. 编辑并保存，确认原标签与笔记保留，新简记与概览关联到正确父文献。
5. 选择 Style 保存方式，检查 `remark:` 新增及显示；未允许更新时保留已有非空简记，其他 Extra 内容完整。
6. 在生成后修改原简记再保存，验证并发保护；多选时检查逐篇更新选择。
7. 验证取消、超时、只读库、已删除条目、重新启用和重启后的行为。

使用自行选择的测试文献，并对照原文检查输出。完整 PDF 分块、原文逐段引用、跨文献综合和实际模型质量不属于当前已完成的自动验证范围。
