# v0.3.0 验证范围

兼容目标是 Zotero 10.0.8，清单允许 `10.0.x`。本页区分协议模拟、打包、原生宿主与用户实际模型验证，不能用其中一层代替另一层。

## 本版自动验证目标

- 核心：快速／均衡／自定义预设、各生成模式、输入与上下文预算、NDJSON 分片、流式完成判定、只提取回答正文、错误与取消。
- 缓存：仅成功结果入缓存、TTL 与容量边界、输入／设置／账户变化失效、草稿修改不会污染缓存、强制重新生成与清空。
- 适配器：原生 HTTP 的增量回调、末尾补发、重定向和取消控制、Ollama 运行信息，以及已有标签／Extra／子笔记的保存保护。
- 订阅授权：模拟官方 OAuth PKCE、state／nonce、身份令牌签名和声明校验、登录管理器存储、刷新／退出、模型目录、SSE 完成、额度与失效处理，不包含网页 Cookie 或 API Key 退路。
- 引擎编排：正确选择本地或已授权 ChatGPT 引擎、来源与模型标记、账户隔离缓存、没有未授权回退。
- 生命周期和打包：双引擎模块加载、设置与菜单注册、清理、必需更新字段、版本与下载一致性、XPI 和源码归档资源。
- Chromium 界面：使用实际控件、CSS 和脚本配合模拟宿主；检查预设、流式显示、缓存、登录状态、模型选择、生成与保存。该层不运行原生 XUL 宿主。

本版最终通过数量与状态由实际执行记录补充，当前不能把上述覆盖目标当作已通过结果。命令见 [README](../README.md)。

## 真实宿主验证

前一版 **v0.2.0** 已在 Linux 上的真实 Zotero 10.0.8 中完成安装和流程验证：[历史 CI 记录](https://github.com/kangweihou522-cmyk/zotero-ollama-local-ai/actions/runs/43392236807)。它证明的是 0.2.0，不能直接证明新增授权、缓存和流式路径均已在 0.3.0 通过。

v0.3.0 的原生测试需要安装本次构建的 XPI，并验证模块启动、真实窗口、原生流式 HTTP、登录管理器可用性、以及合成文献中标签、Style 简记、子笔记和覆盖保护。原生流程使用临时 profile 和回环模型服务，不使用用户文献或 ChatGPT 令牌。只有成功执行的本版记录才可标记为通过。

Windows、macOS 与用户当前全部插件组合尚未联合实测。

## ChatGPT 与性能边界

官方 Sign in with ChatGPT 支持符合资格的开源、本地应用使用用户授权的订阅额度：[快速开始](https://developers.openai.com/siwc/quickstart)、[开源通道说明](https://developers.openai.com/siwc/token-sharing-open-source)、[预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。

自动授权测试使用模拟端点、测试密钥和合成声明，不登录用户实际 Plus 账户。它可验证协议、令牌保护和异常处理，不能证明用户的账户资格、真实模型目录、额度或云端速度。不会要求用户在聊天中提供密码、Cookie 或令牌。

同样，没有在用户的 RTX 3060 6GB、具体 4B 模型和实际文献上测得基准耗时。较小上下文、按需生成概览和缓存可减少工作量；流式预览可更早显示结果。这些不是固定加速倍数或固定每篇秒数的承诺。

## 本机验证步骤

1. 安装 0.3.0，确认两个引擎的设置与生成窗口正常。
2. 使用实际 4B 本地模型，记录快速预设“标签＋简记”的首次与第二次耗时，再单独测试概览；同时查看 `ollama ps`。
3. 确认逐步文本只作为预览，不完整／取消响应不能保存。
4. 重开窗口验证缓存；修改输入、模型或任务后确认重新请求；试验忽略与清空缓存。
5. 选择 ChatGPT 引擎，在官方页面登录并授权，检测实际模型并用少量文献生成。材料会按所选范围发送给 OpenAI。
6. 检查授权失效或额度错误提示；退出后不能继续用旧令牌生成，也不会切到 API Key 计费。
7. 编辑并保存标签、Style 简记和概览，确认旧内容、其他 Extra 字段、逐篇覆盖选择及并发保护正常。

模型生成内容仍需对照材料检查。完整 PDF 分块、原文定位、跨文献综合与实际模型质量不属于当前自动验证结论。
